# 钢铁上市公司上下游冲击传导与经营风险智能体

### 链证 ChainProof

**钢铁产业链风险传导预警系统 · 每一步可追溯到公告原文**（2026 北京市大学生金融人工智能竞赛参赛作品，钢铁侠小队）。

- 在线演示：https://chainproof-steel.streamlit.app/
- 赛题方向：产业链影响分析（主），兼及数据结构化提取、上市公司财务报告分析
- 大模型：通义千问 qwen-plus（国产，阿里云百炼），只用于公告抽取与问题分类，并在测试前冻结
- 第三方模型、开源组件与数据声明：`docs/third_party.md`；可追溯性说明：`docs/traceability.md`

## 赛题方向与本项目的对应

| 赛题方向 | 通知中的考察重点 | 本项目 |
| --- | --- | --- |
| 产业链影响分析 | 产业分析逻辑、证据完整性、量化方法合理性、结论适用边界 | 担保、关联交易、集团关系构成按时点生效的图谱；四条传导规则；预登记事件研究与历史图谱增量检验；未通过的检验降为情景 |
| 数据结构化提取 | 字段提取完整性、格式规范性、表格解析准确性、结果一致性 | 四类公告按 JSON Schema 抽取，逐字段核对原文页码；冻结后独立测试与最终盲测；每个测试集运行 3 次 |
| 上市公司财务报告分析 | 财务指标提取与同比环比计算、非经常性损益、会计口径变化、利润与现金流背离 | 承压评分的 11 个财务与市场指标；企业档案“财报分析”：同比与单季度环比、非经常性损益占比、利润与现金流背离、会计政策或估计变更公告（`src/report_signals.py`）；年报原始科目抽查 30/30 一致 |

## 它回答什么（目标变量，见 `docs/target_definition.md`）

| 问题 | 目标变量 | 由哪部分回答 | 怎么检验的 |
| --- | --- | --- | --- |
| 哪些企业可能率先出现风险？ | **Y1 信用事件**：12 个月内冻结、风险警示、违约、非标审计意见、破产重整，或年度亏损 ≥ 净资产 5% | 风险源预警：公告中已发生的事件 + 财务脆弱性（承压）评分 | 预登记事件研究：被判为“弱”的钢厂 12 个月内发生信用事件的比例 **44.9% vs 12.6%**（3.6 倍，AUC 0.75，样本外 2.6 倍、p = 0.035）；事后：不优于净利率单指标 |
| 风险发生后谁承担损失、最多多少？ | **Y2 损失敞口**：担保余额 ÷ 担保方净资产（代偿上限）；关联交易额单列为“非敞口” | 集团信用通道（担保、关联交易、同集团，计分） | 3 个预注册回测（安泰、凌钢、方大） |
| 价格、停产、政策冲击可能影响哪些企业？ | **Y3 现金流压力**（情景） | 供需情景通道、政策冲击（出口 / 关税 / 反倾销、碳关税、限产） | 两次预注册检验不显著，只作情景、不计分 |

每条结论都标明性质：**已发生事件**（公告事实）、**风险敞口**（关联方违约时才可能转化为损失的或有义务）、**模型预警**（尚未发生信用事件）、**情景假设**。

## 系统组成

| 层 | 做什么 | 关键数据 |
| --- | --- | --- |
| ① 公告抽取 | 冻结版大模型抽取系统（`extraction-freeze-2026-09-24`）读关联交易、担保、产能/检修、质押公告，每个字段校验回原文页码 | 最终盲测关联交易 F1 91.29%（单位修复后 92.15%，非盲） |
| ② 风险源识别 | 公告标题识别已发生的信用事件（冻结、风险警示、违约、非标意见、重整，规则与事件研究相同）+ 抽取出的担保、质押、停产信号 + 财务脆弱性评分 | `data/live/credit_events.csv`、`data/snapshots/` |
| ③ 财务脆弱性（承压评分） | 24 家核心钢厂同行比较，用于风险筛查，不是违约概率：杠杆、短期偿债、造血、盈利、市场、对外担保六维，0–100 分越高越脆弱，≥ 60 为弱；红线与单维极差直接判弱 | 年报原始科目抽查 30/30 一致 |
| ④ 传导 | 从风险源出发，沿担保、关联交易、同集团关系推到其他上市公司；途经企业承压为强或金额低于对方净资产 1% 时按规则不再扩展（风险可能受到缓释）；路径得分是优先核查顺序，不等于损失大小；关联交易额不等于敞口 | 实时图谱 39/42 家有仍有效的披露关系 |
| ⑤ 供需与贸易暴露 | 关系金额统一为万元/亿元、销量单列；客户和供应商占比、连续年数；年报前五名客户/供应商集中度；境外收入占比；铁矿石进口占比 | 96 份年报；`docs/supply_relations.md` |
| ⑥ 财报分析 | 同比与单季度环比；非经常性损益占比；利润与现金流背离；会计政策或估计变更公告（核查提示，不计入评分） | `src/report_signals.py` |
| ⑦ 调度智能体 | 分析一份新公告的 10 步固定计划：识别类型 → 选工具 → 抽取 → 检查证据 → 实体解析 → **入图决策（自动 / 人工复核）** → 承压查询 → **计算敞口** → 传导推演 → 报告；网页展示每一步的工具、结果、决策和理由 | `src/orchestrator.py`；只有抽取一步用模型 |

分析对象为 42 家钢铁产业链上市公司（24 家核心钢厂、2 家节点钢厂、4 家上游、12 家下游），见 `docs/steel_universe.md`。
**监测边界**：风险源限于这 42 家公司及其公告中点名的非上市、境外企业（实时图谱约 520 个非上市节点）；非上市企业自身发生的事件看不到；信用事件另扫描其余 13 家 A 股钢企的公告标题。
武进不锈、广大特材、常宝股份目前没有仍有效的披露关系。多年框架协议按公告写明的有效期生效（`scripts/scan_agreement_periods.py`）。
部分 2026 年度关联交易预计和担保额度公告曾是测试文档：测试结束后以冻结系统第 1 次运行的输出（不是 Gold）并入实时图谱（`scripts/reuse_test_predictions.py`），今后不再用于评测。

证据等级：A 披露确认（公告写明双方与金额，或股权关系已核对来源）；B 部分确认（公司自己披露的产品构成等）；
C 行业推断（只作情景，不计分）。

## 工作原理

```
公告文件 ──► 解析（按页 / 文本块，扫描页自动 OCR）
         ──► 大模型按 JSON Schema 抽取（Qwen，temperature 0）
         ──► 确定性清理：删除无原文依据的金额与日期、恢复原文单位、去掉合计/小计行等
         ──► 证据核验：每个字段必须能在指定页原文中找到，否则标记“需人工复核”
         ──► 输出 JSON / CSV，完整运行日志可审计
```

大模型只负责“读”，所有数字都要经过规则回到原文核对；规则和提示词的每次修改都有版本号与实验记录。

## 支持的公告类型

| 任务 `--task` | 公告 | 抽取内容 |
| --- | --- | --- |
| `pledge` | 股份质押（辅助） | 质押、解除质押、展期；股东、股数、质权人、日期 |
| `capacity` | 产能与项目 | 新建、置换、技改、投产、延期、暂停、终止、**检修/临时停产**；产能变化、投资额、项目所在国、决策原因（贸易政策、环保政策等） |
| `guarantee` | 对外担保 | 担保额度、已提供担保、解除、逾期；担保方→被担保方、关系、金额、债权人、反担保、累计余额 |
| `related_party` | 日常关联交易预计 | 关联方 × 交易类别 × 本年预计金额 × 上年实际金额（产业链供需关系） |

新增公告类型只需在 `src/tasks.py` 注册，不改主流程。

## 支持的文件格式

- PDF：文字版、扫描版、图文混排（扫描页逐页 RapidOCR，置信度 < 0.90 自动转人工复核）
- 图片：png、jpg、jpeg、bmp、tif
- 网页：直接输入网址，或上传 html/htm（正文段落编号、发布日期、GBK 编码）
- Word：.docx，以及老版 .doc（内置读取，无需额外安装）
- Excel：.xlsx、.xlsm、.csv，以及老版 .xls（内置读取）

## 快速开始（Windows PowerShell）

1. 复制 `.env.example` 为 `.env`，填写模型 API（`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`）。**不要提交 `.env`。**
2. 安装依赖：

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   # 需要识别扫描件和图片时再装：
   .\.venv\Scripts\python.exe -m pip install rapidocr_onnxruntime
   ```

3. 启动网页界面：

   ```powershell
   .\.venv\Scripts\python.exe -m streamlit run app.py
   ```

   页面（顶部导航）：
   - **顶部 5 个入口，按阅读顺序排列**，每页底部有“下一步”按钮，会带着当前企业跳转：
     ① 今日预警（今日结论、已发生事件、风险敞口、财务脆弱性、优先核查的传导路径、可信度指标）→
     ② 企业档案（一家企业一页：自身风险与财报分析、关联风险、主要客户与供应商、产品暴露、公告信号）→
     ③ 风险传导（一张图、两条通道：紫色粗线为集团信用通道，计分；蓝灰细线为供需情景通道，不计分；节点颜色为承压等级）→
     ④ 分析新公告（演示案例或上传公告 → 风险预警卡）→
     ⑤ 可信度（最终盲测、年报抽查、预注册回测、产品层检验，包括没有通过的）
   - **明细工具**（下拉）：承压评分全表（逐项拆解、数据来源、敏感性）；信用通道明细（每一步的公告原文、集团财务公司通道）；
     供需情景与政策冲击（冲击幅度、压力指数、碳关税等政策冲击、衔接检查）；公告事实抽取；问一句（全屏）
   - **问一句**：每个页面右下角的圆形按钮，一句话提问；规则优先、模型只在 9 类固定工具中做分类，回答附 5 步调用轨迹

   答辩演示路线：今日预警 → 企业档案（“回测案例”选安泰）→ 风险传导 → 分析新公告（演示案例）→ 可信度。
   没有网络或模型 API 时：“分析新公告”的“演示案例”不需要联网；演示前运行 `python scripts/check_demo.py --pages`，见 `docs/offline_demo.md`。

   **在线演示版**（Streamlit Community Cloud，从 GitHub `main` 分支部署）：在应用的 Secrets 里设置 `CHAINPROOF_PUBLIC = "1"`，
   页面进入只读模式：不调用模型、不联网更新、不写文件，只用仓库里提交的数据和离线演示包。不要把 `LLM_API_KEY` 放进公开应用。
   在线数据由 GitHub 定时任务每天自动更新（见下文“日常运行”），应用随后自动重新部署。
   **在线分析新公告（可选）**：在 Secrets 里再加一个**专用、设了额度上限**的模型密钥（`LLM_API_KEY`，以及与本机一致的
   `LLM_BASE_URL`、`LLM_MODEL`），“分析新公告”就能在线调用冻结版抽取系统。应用侧限额：每次访问 3 份、每份 ≤10 MB / ≤60 页、
   全站每日 30 次（可用 `CHAINPROOF_SESSION_LIMIT`、`CHAINPROOF_MAX_MB`、`CHAINPROOF_MAX_PAGES`、`CHAINPROOF_DAILY_LIMIT` 调整）；
   在线结果不写入实时图谱。不在评分范围的上市公司可以点“临时计算承压”，以 24 家核心钢厂为参照现算，不写入快照。

4. 命令行处理单份公告：

   ```powershell
   .\.venv\Scripts\python.exe -m src.pipeline "公告.pdf" --task guarantee
   ```

5. 批量处理并评分：

   ```powershell
   .\.venv\Scripts\python.exe -m src.batch_runner data\raw\related_test --task related_party --output-dir outputs\my_run\predictions
   .\.venv\Scripts\python.exe -m src.related_party_accuracy_evaluator data\gold\related_test outputs\my_run\predictions --report outputs\my_run\accuracy_report.json
   ```

   各任务对应的评分程序：`src.accuracy_evaluator`（质押）、`src.capacity_accuracy_evaluator`、
   `src.guarantee_accuracy_evaluator`、`src.related_party_accuracy_evaluator`。

## 测试

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

测试包括解析、清理规则、证据核验、评分程序，以及“冻结答案未被改动”“归档报告未被改动”的哈希校验。

## 评测纪律

1. 先提交被测系统，再选测试公告（只看标题），再标注答案并生成 `gold_manifest.lock`（SHA-256），最后运行 3 次。
2. 测试集一旦用于改规则，就降为开发数据；新版本必须换新公告验证。
3. 开发集与测试集按发行人隔离；另预留 8 家核心钢厂作为最终测试集，冻结前不打开（已于 2026-09-26 运行，盲测成绩如上；之后的修复成绩一律标“修复后/非盲”）。
4. 每次运行归档到 `experiments/`，`experiments/registry.csv` 记录任务、模型、提示词哈希与成绩。
5. 标注口径见 `docs/annotation_guidelines.md`，有争议的判断写在各测试集的 `README.md`。

## 输出与审计

每次运行保存在 `outputs/<文件名>/<UTC时间>/`：

| 文件 | 内容 |
| --- | --- |
| `pages.json` | 按页（或文本块）解析的原文 |
| `llm_raw.json` | 模型原始输出 |
| `prediction.json` | 清理后、通过 Schema 校验的结果 |
| `evidence_report.json` | 逐字段证据核验结果 |
| `run_log.json` | 输入哈希、提示词哈希、模型、各步骤耗时与清理动作 |

```
docs/                  实验记录、测试报告、标注规范
experiments/           运行归档

```

## 验证边界

- 证据核验能证明“输出的每个字段都来自原文”，但不能证明“原文里的每一行都被抽到了”；召回率只能用人工标注的答案评估。
- 承压评分是同行相对排名，衡量当前财务脆弱性，不是违约概率，也不直接衡量对某一特定冲击的承受能力；事件研究中硬信用事件只有 6 条，结论是“事件发生率高多少”，不是概率模型。
- 回测只有 3 个案例；供需产品层两次检验不显著。全部验证结果（包括没通过的）见网页“可信度”页和 `docs/`。

## 日常运行

线上数据由 GitHub 定时任务（`.github/workflows/daily-update.yml`）每天北京时间 06:30 自动更新：在 GitHub 的服务器上运行下面第一条命令，
把结果提交到 `main`，Streamlit Cloud 随后自动重新部署；也可在仓库 Actions 页面手动运行。模型密钥保存在仓库的 Secrets 中。
本机仍可手动运行：

```powershell
python scripts/daily_update.py                       # 查新公告 → 冻结系统抽取 → 识别信用事件 → 重建图谱 → 承压评分 → 传导路径 → 日报
python scripts/daily_update.py --since 2025-05-01     # 补抓一段时间的公告
python scripts/daily_update.py --no-network           # 只用已有数据重建
```
