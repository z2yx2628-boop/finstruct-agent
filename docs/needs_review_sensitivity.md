# 敏感性分析：传导路径是否依赖“需复核”的公告（事后分析，2026-10-14）

本分析在已知“约一半公告标为需复核、批量建图仍使用”之后设计，**不是预登记检验**，只用于说明结论的稳健性。
脚本：`scripts/sensitivity_needs_review.py --as-of 2026-10-10`；结果：`data/eval/needs_review_sensitivity_2026-10-10.json`。
不改动实时图谱 `data/chain/live`。

## 方法

用同一批冻结抽取结果（实时图谱的全部来源，共 287 份公告）、同一个承压快照（2026-10-10）和同一套传导规则，建三版图谱并比较关键路径：

| 版本 | 规则 |
| --- | --- |
| A 全部（基准） | 与实时系统相同，使用全部 287 份公告 |
| B 整份剔除 | 只要一份公告有任何一项核对未通过（状态为“需复核”），整份公告不入图 |
| C 逐条剔除 | 保留全部公告，只剔除**交易方名称或证据摘录在公告全文中找不到原文**的记录；证据摘录能在其他页找到（页码错、内容对）的记录保留 |

“需复核”的判定按页核对：只要证据摘录不在模型标注的那一页，整份公告就标为需复核。此前测试已发现模型常把表格行的页码标早一页而数值正确（`docs/related_party_test_evaluation.md`），因此 B 会连带剔除大量内容正确的记录；C 按记录判断，更接近“错的数据是否进了图”。

## 结果

287 份公告中 149 份核对全部通过，138 份（48.1%）为需复核。需复核公告中的问题：证据摘录在其他页找到 340 处；证据摘录在全文中找不到原样文字 470 处（多为模型把表格单元格拼接成一句，内容未必错误，按保守口径一律剔除）；交易方名称在原文中找不到 62 处；其余 387 处为金额缺失、被担保方未写明等，本身不产生错误关系。

| 指标 | A 全部 | B 整份剔除 | C 逐条剔除 |
| --- | ---: | ---: | ---: |
| 入图公告 | 287 | 149 | 287 |
| 剔除的记录 / 事件 | — | — | 327 / 190 |
| 披露关系边 | 2,564 | 443 | 2,072 |
| 风险源 | 13 | 7 | 10 |
| 关键路径 | 27 | 16 | 24 |
| A 的前 10 条仍在 | — | 0 / 10 | **10 / 10** |
| A 的前 20 条仍在 | — | 7 / 20 | **20 / 20** |
| A 的 27 条仍在 | — | 9 / 27 | **24 / 27** |
| 新出现的路径 | — | 7 | 0 |

C 中消失的 3 条路径都是友发集团子公司之间的担保（四川云钢联供应链、天津友发供应链、天津友发德众钢管 → 友发集团），对应的担保记录证据摘录与原文不一致，剔除合理。

## 结论

1. **逐条剔除无原文依据的记录后，排名前 20 的传导路径全部保留，没有新增路径**：排在前面的路径（凌钢—本钢—鞍钢等）不依赖核对失败的记录。
2. 整份剔除会删去 83% 的关系边、前 10 条路径全部消失，原因是关联交易公告多为长表格，页码错位使整份公告被标为需复核。这说明按整份公告判定过于粗糙；今后入图应改为按记录判定（计划在下一版实施，需在新数据上验证）。
3. 本分析是事后设计的，三版结果并列报告；B 版的结果同样如实列出。
