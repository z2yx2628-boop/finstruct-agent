# 事件研究：承压评分能否事前区分信用事件（预注册，2026-09-29）

本文件在收集任何事件数据、生成任何历史快照之前写定并提交。结果出来后不改；
之后的任何修改（事件规则、样本、评分方法）只能称为“修复后/校准后”，与原结果并列报告。

目标变量定义见 `docs/target_definition.md`，本检验针对 **Y1 信用事件**。

## 1. 要回答的问题

在评估日被承压评分判为“弱”的核心钢厂，未来 12 个月内发生信用事件的比例，是否明显高于其他钢厂？

## 2. 样本

- 企业：`data/manifests/steel_universe.csv` 中 `core_analysis_target = Y` 的 24 家核心钢厂。
- 评估日：2019-04-30、2020-04-30、2021-04-30、2022-04-30、2023-04-30、2024-04-30、2025-04-30（共 7 个，窗口互不重叠）。
- 观测单位：企业 × 评估日。某企业在评估日无法算出总分（没有该期财务数据）时剔除，并记录。
- 预测窗口：(评估日, 评估日 + 12 个月]。2025-04-30 的窗口止于 2026-04-30，已完整。

## 3. 预测变量：历史承压评分

- 方法：承压评分 v1（`src/fragility.py`，本文件提交时的版本），由 `scripts/update_all.py --as-of <日期> --offline --no-guarantee --out data/event_study/snapshots` 生成。
- 只使用评估日已公开的数据：财务按法定截止日（`src/quarterly.py`），行情截至评估日。
- **不含**对外担保维度和公告事件降档：历史年份没有完整的担保与事件抽取结果。该维度记为缺失，权重在其余五个维度间重新分配。
  因此本检验评价的是“财务 + 市场”两层，不是完整的实时评分。
- 分组：`tier = weak` 为“弱”，其余（中、强）为“非弱”。

## 4. 结果变量：Y1 信用事件

某企业在窗口内出现下列任一事件，Y1 = 1。

### 4.1 硬事件（公告标题）

来源：新浪财经公告列表（`scripts/collect_credit_events.py`），2019-01-01 至 2026-04-30 的全部公告标题。
先排除标题含“解除、撤销、解冻、终止、申请撤销、摘帽、完成、结束、补充更正、更正、英文、摘要、说明会、问询、回复、法律意见、核查意见”的公告，再按下表匹配：

| 类型 | 标题匹配（正则） |
| --- | --- |
| guarantee_default 担保代偿或逾期 | `逾期担保\|担保.{0,12}(逾期\|代偿)\|承担.{0,6}(连带)?(保证\|担保)责任` |
| debt_default 债务逾期或违约 | `(借款\|贷款\|债务\|票据\|债券\|融资\|商票).{0,10}(逾期\|违约\|未能.{0,4}(兑付\|偿还\|清偿))\|未按期(兑付\|偿还)\|债务违约` |
| freeze 司法冻结 | `(股份\|股权\|资产\|账户\|银行账户).{0,10}(司法冻结\|被冻结\|轮候冻结\|司法拍卖\|司法划转)` |
| st 风险警示 | `退市风险警示\|其他风险警示\|实施.{0,4}风险警示` |
| audit 非标准审计意见 | `非标准(无保留)?(审计)?意见\|保留意见\|无法表示意见\|否定意见` |
| rating 评级下调 | `评级.{0,8}(下调\|调低\|下降)\|(下调\|调低).{0,8}评级\|负面观察\|展望.{0,4}负面` |
| restructuring 重整 | `破产重整\|预重整\|破产清算` |

人工核对（与评分合并**之前**完成）：对每条匹配标题逐条确认 `include = Y/N` 并写明理由。只在以下情况为 N：
事件主体不是该公司、其控股子公司或其控股股东（冻结类限于控股股东所持该公司股份）；标题是例行制度、历史回顾或对他人的事项；
同一事件的重复进展公告（保留最早一条）。核对结果写入 `data/event_study/events_reviewed.csv` 并提交，提交后冻结。

### 4.2 软事件（财务数据）

某年归母净利润 < 0 且亏损额 ≥ 该年末股东权益合计的 5%（新浪财务摘要）。事件日 = 该年报法定截止日（次年 4 月 30 日）。
例：评估日 2023-04-30 的窗口包含 2023 年报（截止 2024-04-30）；评估日当天已公开的 2022 年报不在窗口内。

## 5. 判定标准

主检验（复合 Y1 = 硬事件或软事件）：

- 提升倍数 = 弱组事件率 ÷ 非弱组事件率；单侧 Fisher 精确检验。
- **通过**：提升倍数 ≥ 1.5 且 p < 0.05。
- **方向一致但不显著**：提升倍数 ≥ 1.5 且 p ≥ 0.05。
- **未通过**：提升倍数 < 1.5。

次要结果（报告，不作为通过条件）：

1. 总分对 Y1 的 AUC，以及按企业重抽样（2000 次）的 95% 区间；预期 ≥ 0.60。
2. 只看硬事件的两组事件率（事件少，只作描述）。
3. 按评估日分年的两组事件率。
4. 探索：非弱企业中，同集团（按 `groups_as_of` 取评估日的集团归属）另有上市成员为弱时，其事件率是否更高。只作描述。

## 6. 已知偏差与限制（事先说明）

- 同一企业在 7 个评估日重复出现，观测不独立；Fisher 检验会高估显著性，AUC 区间按企业重抽样部分纠正。
- 软事件与评分中的盈利维度相关（亏损有持续性）。这是真实的预测信息，但会让结果好看，所以硬事件单独报告。
- 承压评分 v1 的阈值在 2026-09-26 用安泰回测（评估日 2025-01-31）和实时数据校准过；2024、2025 两个评估日与回测期重叠，
  2019–2023 五个评估日为样本外。结果按样本外与重叠期分别报告。
- 硬事件只看标题，可能漏掉标题不写明的事件（例如年报中披露的逾期）。漏检使两组事件率同时偏低。
- 历史财务取自当前可下载的新浪财务摘要，个别年份可能是追溯调整后的数字，而不是当年首次披露的数字；行情为前复权价格。
- 核心钢厂多为国企，真实违约少；结论是“事件发生率高多少”，不是违约概率模型。

## 7. 执行顺序

1. 提交本文件、`docs/target_definition.md` 和所用脚本（尚未运行）。
2. 运行 `scripts/collect_credit_events.py`，得到候选事件；人工核对，提交 `events_reviewed.csv`（冻结）。
3. 运行 `scripts/update_all.py` 生成 7 个历史快照（只读缓存数据，`--offline`）。
4. 运行 `scripts/run_event_study.py`，结果写入 `docs/event_study_results.md`，按第 5 节判定，照实报告。
