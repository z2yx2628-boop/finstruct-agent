# 离线演示包与演示前检查

答辩现场可能没有网络、模型 API 可能限流或失效。演示包保证“分析新公告”在**不联网、不调用模型**时仍能完整演示，
而且显示的内容与冻结系统真实产出一致，不是事后手写的结果。

## 演示包里有什么

`data/demo/`（约 1.4 MB，随仓库提交）：6 份真实公告原文 + 冻结系统当时保存的抽取结果 + `manifest.json`（每个文件的 SHA-256）。

| 案例 | 评估日 | 图谱 | 用途 |
| --- | --- | --- | --- |
| 安泰集团担保 | 2025-01-31 | backtest_antai_fix1 | 回测；校准后担保路径排第 1（原始回测排第 2，记为部分通过） |
| 凌钢股份为凌钢集团担保 | 2024-04-30 | backtest_linggang_fix1 | 样本外正例：亏损披露前约 11 个月列为第 1 条路径 |
| 方大特钢为方大炭素担保 | 2025-02-28 | analysis_v1_fix1 | 样本外反例：看到关联担保但不误报 |
| 凌钢股份股东质押 | 2025-01-31 | live | 质押严重度按股东持股比例判断 |
| 鞍钢股份 2026 年日常关联交易 | 2026-09-27 | live | 最终盲测文档之一（修复后抽取结果） |
| 方大特钢检修 | 2026-09-27 | live | 产能/检修类公告 |

重新生成：`python scripts/build_demo_pack.py`（需要本机的 `data/raw/` 和 `outputs/`，这两处不进 git）。

## 工作方式

- **页面“分析新公告 → 演示案例”**（默认第一个标签）：选案例直接生成预警卡片，评估日和图谱按案例自动设定。
- **“上传新公告 → 分析设置 → 离线模式”开关**：开启后上传文件也不调用模型；只有与演示包文件**字节完全相同**（SHA-256 一致）的文件才能分析，其他文件会提示关闭离线模式。
- **自动兜底**：离线模式关闭时正常调用模型；如果调用失败且文件在演示包里，自动改用离线回放。
- 每张回放卡片的结论下方都有一行说明“离线回放：未调用模型……”，不会把回放冒充成现场抽取。

注意：`live` 图谱会随每日更新变化，用它的三个案例（质押、鞍钢、检修）的路径可能与今天不同；三个回测案例用固定图谱，结果不变。

## 演示前检查清单

在演示用的电脑上（最好是从 GitHub 新克隆的目录）依次运行：

```
python scripts/check_demo.py --pages
python -m pytest -q
```

`check_demo.py` 会断网、移除 `LLM_API_KEY`，然后检查：演示包文件完整且哈希一致；6 个案例都能生成卡片；
三个回测案例的结论与 `docs/backtest_cases.md` 一致；`--pages` 时逐页渲染全部 9 个页面，并点击演示包按钮。
最后一行显示“离线演示就绪”即可。

现场备用：
- 断网：只用“演示案例”标签，或在上传时打开“离线模式”。
- 页面打不开：用 `streamlit run app.py --server.port 8502` 换端口；仍不行就播放录屏。
- 提前在今日预警底部“数据更新”里点一次“立即更新”，让今日预警显示当天数据；现场不要依赖联网更新。
