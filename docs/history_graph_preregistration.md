# 历史图谱与增量检验：沿披露关系的传导，是否在企业自身状况之外多解释了风险（预先登记，2026-09-30，建图和运行前写定）

## 要回答的问题
项目主张：风险会沿公告披露的**担保（R1）和关联交易 / 供需（R2）**关系传到其他企业。事件研究（`docs/event_study_results.md`）
只检验了“自身承压为弱的企业更容易出事”，没有检验传导。本检验问：**在自身档位相同的企业中，被他人的风险沿披露关系波及的企业，
12 个月内发生信用事件（Y1）的比例是否更高？**

## 先说明：这是非盲检验
- 结果变量 Y1（`data/event_study/panel.csv`，168 个企业×评估日）早已算出，并看过按承压档位的汇总；
  事件研究还报告过一项描述：非弱企业中“同集团另有弱成员”的事件率 17.9%（5/28），没有的 11.0%（10/91）。
- **没有看过的**：历史图谱尚不存在，任何企业在任何评估日“是否被波及”都还没有计算。
- 因此本检验的规格在建图之前写定，但结果变量已知，只能称为“**预先写定规格的非盲检验**”，不能与预注册事件研究相提并论。

## 历史图谱怎么建（写定后不改）
- **公告范围**：24 家核心钢厂 2019-01-01 至 2025-04-30 的日常关联交易和担保公告，标题取自已缓存的公告列表
  （`data/event_study/titles/`），按系统已有的标题规则（`scripts/find_analysis_corpus.classify`）筛选：
  `python scripts/backfill_history.py` 选出 595 份新公告（另有 67 份已被冻结系统抽取过，直接沿用；1 份测试文档没有冻结输出，不抽取）。
- **抽取**：只用冻结版系统（`extraction-freeze-2026-09-24`），`scripts/run_analysis_corpus.py --split hist`；
  **不因本检验修改抽取器、提示词或传导规则**。抽取错误照样保留。
- **建图与路径**：`scripts/build_history_graph.py`：全部冻结抽取结果 → `data/chain/hist`；每个评估日只使用当日已公告、仍在有效期内的关系
  （`src/validity.is_active`）；承压状态用事件研究冻结的快照（`data/event_study/snapshots/<日期>`），不重算；
  实时图谱专用的“公告标题识别信用事件”不加入。
- `scripts/run_propagation.py` 只增加一列 `nodes`（路径经过的实体编号），不改路径的生成与打分。

## 暴露定义
- **E1（主）**：某钢厂在评估日被一条关键路径波及：路径起点不是它自己，路径不含行业近似（R4），且从起点到它之间至少经过一步担保（R1）或供需 / 关联交易（R2）。
- **E2（次，只报告）**：被任一不含 R4 的关键路径波及（包括只经集团关系 R3 的路线）。

## 统计
- **样本**：2020–2025 年 6 个评估日（4 月 30 日）× 24 家 = 144 个企业×评估日。2019-04-30 缺 2018 年公告的关系，只作敏感性分析。
- **主统计量**：按“自身是否为弱”分层，被 E1 波及者的实际 Y1 事件数减去按所在层事件率计算的预期数。
- **p 值**：单侧置换检验，在层内打乱 E1 标签 10 000 次，随机种子 20260930。
- **覆盖门槛**：先看图谱能否看到这些企业。2020–2025 年各评估日平均至少 50% 的核心钢厂有生效的披露关系，
  且被 E1 波及的企业×评估日至少 10 个，否则结果只报告、**不作判定**（图谱太稀，检验不具信息量）。

## 成功标准
| 判定 | 条件 |
| --- | --- |
| 通过 | 超出预期事件数 > 0，且单侧 p < 0.05 |
| 方向一致但未显著 | 超出 > 0，p ≥ 0.05 |
| 未通过 | 超出 ≤ 0 |

只报告、不作判定：E2；去掉 3 条控股子公司破产事件；按“自身档位 × 评估日”分层；加入 2019 年；
逐年留出的逻辑回归 AUC（只用净利率 / 净利率 + 承压评分 / 再加 E1）。

## 事先说明的局限
- 只补建了关联交易和担保；产能（停产、检修）和股权质押信号没有补建，历史图谱的起点比实时图谱少。
- 标题列表只覆盖 24 家核心钢厂；图谱中的其他上市公司（安泰集团等）历史关系不完整。
- 事件研究的承压快照没有担保维度（当时没有历史担保数据），本检验不回头补入，以免改变已冻结的评分。
- 无论结果如何，都写在本文件末尾，并在网页“可信度”页和计划书中如实报告；不改变 E1 定义、样本、门槛后重跑并称为验证结果。

## 运行顺序
1. 提交本文件和相关脚本（`run_incremental_test.py` 会检查已提交）。
2. `python scripts/backfill_history.py`
3. `python scripts/download_capacity_holdout.py --split hist`
4. `python scripts/run_analysis_corpus.py --split hist`（约 13 小时，可中断，重跑时从断点继续）
5. `python scripts/build_history_graph.py`
6. `python scripts/run_incremental_test.py`（结果追加到本文件末尾）
