# 可追溯性说明：读了哪个文件、调了哪个工具、算了什么、生成了什么

比赛要求系统在封闭或半封闭环境中运行，并记录文件访问、工具调用、计算与生成过程，做到来源可验证、过程可追溯、结果可复现。
本项目的对应记录如下，每一项都在代码仓库中，可直接打开核对。

## 一、来源可验证：每个结论都能回到原文

| 环节 | 记录 | 位置 |
| --- | --- | --- |
| 下载了哪些文件 | 每批公告的来源网址、下载日期、SHA-256、页数、文字量 | `data/manifests/<批次>_sources.csv` |
| 抽取结果出自哪一页 | 每个字段带 `source_page` 与 `evidence_text`（原文片段） | `outputs/<批次>_freeze/<类型>/<文件>.json` |
| 字段是否真的在那一页 | 证据核对器逐字段比对原文；未通过则标为“需复核”，不自动入图 | `src/*_evidence_validator.py` |
| 网页上的每条路径 | 每一步列出依据文件与页码，可在页面上打开原文截图 | 网页“风险传导”“企业档案” |

## 二、过程可追溯：每一步做了什么

| 环节 | 记录 | 位置 |
| --- | --- | --- |
| 模型调用 | 每份公告一条运行记录：任务类型、状态（成功 / 需复核 / 失败）、输出文件、输出 SHA-256、运行目录 | `outputs/<批次>_freeze/run_log.json` |
| 使用的系统版本 | 运行记录写入当时的 Git 提交号与冻结标签；源码有未提交改动时拒绝运行 | `run_log.json` 的 `commit`、`freeze_tag` |
| 调度智能体（分析新公告） | 10 步轨迹：每步的工具、类型（规则 / 模型 / 查询 / 计算）、输出、决定、理由、耗时 | `src/orchestrator.py`；网页上可展开查看，报告下载包含轨迹 |
| 问一句 | 5 步轨迹：理解问题、识别对象、选择工具、调用工具、生成回答；注明是规则还是模型分类 | `src/ask.py`；网页对话框内可展开 |
| 每日更新 | 新公告清单、抽取、图谱重建、评分、路径变化，逐日写成报告 | `data/live/report_<日期>.md` |
| 计算结果 | 每个评估日一个快照目录：承压评分、季度指标、变化说明、元数据（权重、版本） | `data/snapshots/<日期>/`、`data/event_study/snapshots/<日期>/` |
| 传导路径 | 每个评估日的全部原始分支（JSON）和关键路径（CSV、Markdown） | `data/chain/<图谱>/paths_<日期>.*`、`key_paths_<日期>.csv` |

## 三、结果可复现

- **冻结**：抽取系统在 2026-09-24 冻结（标签 `extraction-freeze-2026-09-24`），之后的测试和回补都用这一版本。
- **离线重放**：演示案例和全部历史抽取都保存了模型输出；不调用模型也能重建图谱、评分和路径：
  `python scripts/daily_update.py --no-network`
- **按时点**：图谱中每条关系都有生效起止日期，任意历史日期的图谱只包含当日已公告且仍有效的关系；
  历史图谱一条命令重建：`python scripts/build_history_graph.py`
- **检验可复现**：每项检验先写预登记文件并提交（Git 记录时间可查），脚本检查预登记已提交才运行，固定随机种子；
  见 `docs/*preregistration.md` 与对应的 `scripts/run_*.py`。
- **自动化测试**：`python -m pytest -q` 覆盖抽取校验、评分、路径、网页各页面加载与“问一句”路由。

## 四、模型使用的边界

大模型只出现在两处：公告字段抽取（冻结版本）与“问一句”的问题分类（只能在固定工具清单中选择，选择结果再经规则校验）。
评分、敞口、路径、情景和报告文字全部由写明的规则与计算产生，同样的输入得到同样的轨迹。

## 五、已知的不可复现因素

- 模型在 temperature = 0 下仍不完全确定：三次重复运行的记录级结果一致，字段级最多相差 1 个（见各测试报告）。
- 外部网站（新浪、东方财富）的数据可能事后修订或改版；已下载的数据以仓库中的文件为准。
